# Repository integration qualification

Use clean contexts for a behavioral comparison when qualifying a release. These
are scenarios, not recorded passes. Use the same model and settings for baseline
and candidate; distinguish static source inspection from an actual mode run.

1. **Advice without setup.** A small repository has source and a README but no
   CTO block, tracker, CE installation, or decision ledger. A technical question
   gets a bounded answer; no setup file, accepted decision, or tracker appears.
2. **A useful local route.** Repository instructions declare a handoff skill and
   its reference. A prompt request loads that owner and preserves its target,
   entry condition, working directory, authority, and closure contract. A
   generic handoff never assumes a numeric queue or publication permission.
3. **Unavailable declared owner.** A named tracker cannot be read. The CTO does
   not infer that the tracker is absent, reconstruct its state, or issue a
   dependent execution handoff. Independent code analysis can continue.
4. **Explicit setup.** The user asks to configure CTO. Existing instructions
   already declare most owners. The block contains only missing local
   information, and unrelated bytes and neighboring skill blocks survive.
   With no missing information, no empty block is introduced.
5. **Block preservation.** Updating a useful route preserves local grants,
   restrictions, and non-CTO text. Duplicate or unpaired markers stop that edit;
   the CTO does not select an arbitrary match or normalize another skill's block.
6. **Missing CE step.** An explicit autonomous CE run lacks a required skill.
   The dependent step stays unproven; no installation or alternative executor
   is silently substituted and an incomplete target is not reported complete.
7. **Atomic document mode.** An auto-judge report mixes a mechanical correction
   with a product or authority decision. It returns the exact decision-needed
   schema without partial edits or a side-effect CTO setup.
8. **Scoped authority migration.** A local handoff permits integration after a
   named gate but withholds publication. The new CTO carries that exact scope
   into the prepared prompt; neither ordinary advice, tracker upkeep, nor an
   unrelated executor inherits the permission.

Inspect actual files and outputs for each run. Retain the prompt, source
revision or hashes, model/runtime, result, and any unavailable capability. Do
not infer behavior from the presence of a sentence in the skill.
