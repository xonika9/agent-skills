# README contract

A README serves a human deciding what the project is and how to run the normal path.

## Default content

- Purpose and current status.
- Supported setup prerequisites.
- The shortest verified setup/run example.
- Normal usage and main outputs.
- Links to canonical architecture, operations, contribution, and agent instructions when those exist.

## Existing README

Treat it as user-owned. Merge corrections and missing sections; do not replace its voice, positioning, caveats, or examples merely to fit a template. A user request for a full rewrite is sufficient authority, but still preserve factual content unless the user also changes it.

## Duplication

Canonical facts may be summarized for human readability. Keep the command or rule in one authoritative location and link there when full detail would drift.

## Verification

Run the primary setup or usage command when safe. Confirm links and paths exist. Label platform-specific or untested instructions explicitly.
